# 交接说明 · DSH → Code Agent

## 1. 一句话

`全站仪导线观测记录表.svg` 是**空白印刷表**的矢量还原（无任何数据、无手写、无位图）；`geometry.json` 给出每个录入/计算格的精确框位（viewBox + 百分比）。Code Agent 只需：把 SVG 当视觉层铺满容器，按 `geometry.json` 的百分比把输入框/计算值放上去。

## 2. 哪些是"量出来的"（可直接信）

- **12 列边界 + 17 条行边界**：四点透视校正后逐线检测，残余偏差 ≤ 2 单位（≤ 0.12 % 表宽）。
- **行高 54.0、表头 144.8、每站 4 行 = 216.0**：实测行高 53.0–55.0，取均值后统一；4 个分块线位置与实测差 ≤ 0.5 单位。
- **合并结构**：用"某条线在某个列带上是否存在"的对比度检测逐格验证过，不是看照片猜的。结论见 `视觉规格.md` §4/§6。
- **斜线端点**：对候选"角对角"线段做暗度打分，最佳解与角对角偏差 ≤ 3 px，故取严格角对角。
- **线宽**：外框 3.0 / 分块与表头底线 2.2 / 内线 1.3（由 FWHM 中位数换算）。
- **字位**：每块文字的上/左/基线按墨迹框对齐（标题、表头信息行、12 列表头、盘位 L/R、水平角值 L/平均值/R）。

## 3. 哪些是"推出来 / 理想化"的（须知）

| 项 | 做法 | 影响 |
|---|---|---|
| 列宽 | 照片实测 141.3–143.4 / 88.0–89.0 / 164.6–168.6 三档，按档归并为 **142 / 88 / 167** | 单列最多差 2 单位（0.12 %），视觉无感；表格更"整" |
| 行高 | 实测 53.0–55.0，统一成 54.0 | 累积最大 1.5 单位 |
| 纵向物理比例 | 照片纸张边被裁掉，改用"汉字方块"校准（墨迹长宽比中位数 1.00）+ 字号自洽（12 pt / 18 pt）间接定标 | 误差 < 2 %；若日后有实尺可再标定一次 |
| 字体 | 中文用 HarmonyOS Sans SC（项目自带），标题用宋体栈 | 字形与照片的黑体略有差异，排布一致 |
| `高(m)` 的 (m) | 照片上这只 (m) 明显比其它单位的 (m) 大（约 29 vs 23.5 单位），照印 | — |
| 表头 `指标差`、`竖直角` | 照片上为加粗，照印 700 | 若下游统一字重，请保留这两列加粗 |
| 水平角值三格 | 照片为 r1 / r2–r3 / r4 三格（中间格跨两行） | **不要**按"4 行等分"来做 |

## 4. 下游必读（最容易踩的三个坑）

1. **行序是 L / R / L / R**，目标列是**每 2 行一个目标**（①①②②），不是旧版"目标①盘左、目标②盘左…"的 L/L/R/R。
   - 推论：2C、指标差、竖直角、平距、高差是**每目标一格（跨 2 行）**；斜距、水平度盘读数、竖盘读数是**每行一格（4 格）**。
2. **印刷的 `L` / `平均值:` / `R` / 盘位 `L R L R` 是静态字形**，数据要写在它们旁边/下面的留白里；`geometry.json` 中 `role:"static"` 的框是"避让区"，别把输入框压上去。
3. **斜线格**（测站/仪器高、目标/棱镜高）只给了三角内接矩形；任何拉伸/居中都要以该矩形为边界，跨过斜线就穿帮。

## 6. 遗留问题（需要用户/Code Agent 确认）

1. **斜线格里"测站号"与"仪器高"的落位**：目前给的是三角内接矩形（测站号在标签下方、仪器高在格底偏右）。若正式页面想改成"标签右侧紧贴输入"，只需在同一三角形内右移，不改线。
2. **水平角值的 `平均值` 是录入还是纯计算**：`geometry.json` 标为 `computed`。若老师要求手填，把它改 `input` 即可（框已在）。
3. **2C / 指标差 / 竖直角 写在哪一行**：印刷结构是"每目标一格"，建议写在该 2 行合并格的垂直居中；若要求"写在盘左行"，请把值放 `s{i}-r{奇}-…` 的框内并把合并格留空——两种都能落位。
4. **表头信息行的下划线**：照片空白表上**没有**印刷下划线，只有留白；如正式页面希望加细下划线，请自行在 `meta-*` 框底部画 0.5 px 线（不要改 SVG）。
