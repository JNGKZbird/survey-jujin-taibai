# 单表导入导出

一个项目包含七张表：表一导线、表二水准、表三角度、表四导线汇总、表五水准汇总、表六三角高程平差、表G 导线计算。单表导出只把当前表写进文件，其余六表在文件里各是一张空白页；单表导入只替换文件里标明的那张表，其余六表与项目其他数据不受影响。

表四/表五/表六的正文是计算覆盖层，单表文件实际携带的是它们的表头、姓名与备注（表五会带走全部页，表六带表头与整列备注）；导入后正文仍由当前项目的表一/表二重算。表G 不同：每页的 11 行、页角色（开始页 / 续页）、来源记录与 `settings.traverseCalc` 会随文件带走，导入后原样放回，不按当前项目的表一重算。

## 三种导出

| 入口 | 得到什么 | 能导入到哪里 |
| --- | --- | --- |
| 顶栏「导出」；选项 → 数据 →「导出本表 JSON」 | 当前表一张表 | 本软件（按单表识别），只替换该表 |
| 选项 → 数据 →「导出整个项目（七表）」；项目菜单 →「导出当前项目（七表 JSON）」（旧 v1 信封） | 当前项目七张表 | 本软件；旧 `正式版` 也能导入，但会忽略表四/表五/表六与表G |
| 项目菜单 →「导出全部项目」 | 整个项目库（v2 信封） | 本软件，整体替换项目库 |

单表文件不携带联立映射、项目元数据、显示大小/缩放；`projectName` 与 `tableName` 只是给人看的备注。

## 单表文件格式

```jsonc
{
  "app": "survey-jujin",
  "kind": "table",
  "formatVersion": 1,
  "table": "leveling",
  "tableName": "表二 水准",
  "projectName": "实习一组",
  "exportedAt": "2026-10-28T12:00:00.000Z",
  "state": {
    "version": 1,
    "settings": {
      "limitsRev": 1,
      "traverse": { "mode": "VA", "c2Limit": 12, "indexLimit": 25, "halfDiffLimit": 20 },
      "leveling": { "grade": "IV" },           // 目标表：导出时的真实设置
      "angle": { "limit": 20, "font": "harmony" },
      "traverseSummary": {},
      "levelingSummary": { "legPages": 1 },
      "trigSummary": {
        "sideFormula": "sqrt",
        "sideLimit": 60,
        "sideLinear": 0.4,
        "closureLimit": 40,
        "closed": true
      },
      "traverseCalc": {
        "angleDir": "ccw",
        "fBetaCoef": 40,
        "kDen": 4000,
        "connDir": "left",
        "coords": { "pn": "35958.860", "pe": "6010.070", "tn": "", "te": "" },
        "coordsPrompt": "pending"
      }
    },
    "pages": {
      "traverse": [ /* 一张空白页 */ ],
      "leveling": [ /* 真实页 */ ],
      "angle": [ /* 一张空白页 */ ],
      "traverseSummary": [ /* 一张空白页 */ ],
      "levelingSummary": [ /* 一张空白页 */ ],
      "trigSummary": [ /* 一张空白页 */ ],
      "traverseCalc": [ /* 一张空白页 */ ]
    },
    "ui": { /* 完整默认 UI；active=leveling，pageIndex.leveling=0 */ }
  }
}
```

示例省略了空白页与 `ui` 的内部字段；实际文件里它们是完整对象，`state` 整体是软件真实的 v1 状态。目标表换成表四/表五/表六时，真实页里是 `meta`、表五的 `names` 与表六的 `remark`，正文仍不落盘；目标表是表G 时，真实页里是 `meta`、`role`、`source` 与 11 行 `rows`。

- `kind: "table"` 是唯一可靠的单表标志。
- `table` 只会是 `traverse`、`leveling`、`angle`、`traverseSummary`、`levelingSummary`、`trigSummary`、`traverseCalc` 之一。
- `formatVersion` 目前固定为 `1`；数字字符串 `"1"` 也接受，但会按数值校验。
- `state` 是合法的 v1 状态：目标表放真实页与该表设置，其余六表各放一张软件定义的空表页与默认设置。因此它能通过现有 `normalizeState(strict: true)`，页数上限仍是 100。
- 顶层故意没有 `version`、`data`、`schemaVersion`。旧 `正式版` 的 `normalizeState` 要求 `version: 1`，会拒绝单表文件，不会把它当成项目数据导入而清空其他表。

不能用「其余表是不是空」来猜单表：一个合法的七表项目也可能本来只有一张表有数据。识别只认 `kind`。

## 识别规则

导入统一走 `JujinTransfer.detect(parsed)`，按以下顺序判定，先命中先返回：

1. 不是对象（含数组、`null`）→ 拒绝：「这不是可识别的记录 JSON」。
2. `schemaVersion` 大于 2 → 拒绝：项目库版本高于当前支持的 2。
3. `schemaVersion` 等于 2 → 全部项目信封，走原有「导入全部项目」流程。
4. `kind === "table"`：
   - `formatVersion` 大于 1 → 拒绝：单表格式版本过高；
   - `formatVersion` 不是 1、`table` 不认识、或 `state` 不是对象 → 拒绝并说明原因；
   - 否则 → 单表。
5. `kind` 存在且不是 `"table"` → 拒绝：「无法识别的文件类型」，避免把未来格式误当旧 v1。
6. 其余 → 旧 v1 项目信封，走原有导入（仍由它自己校验 `version: 1`）。

`schemaVersion` 优先于 `kind`；单表文件本身不带 `schemaVersion`，两者不会互相干扰。

单表文件与单个 v1 文件都受 8 MB 上限；全部项目信封受 32 MB 上限。

## 导入单表

确认框会写明：来自哪个文件、导入哪张表、多少页、替换当前项目的该表数据与该表设置（表G 即 `settings.traverseCalc`），其余六表不动，且无法撤销。

确认后：

1. 桌面版先强制备份当前项目（原因 `import-table`），备份失败只提示，不拦住导入。
2. 只替换 `state.pages[表]` 与 `state.settings[表]`；页索引归零。
3. 当前项目、其余六表、联立映射、显示大小/缩放、项目名都保持不变。
4. 界面切到该表并滚动到顶部，随即保存。
5. 文件里的 `ui`（缩放、页面视图等）不导入。

导入的是「替换」，不是合并或追加。

### 表四 / 表五 / 表六 / 表G 的特殊性

- 表四单表文件只带 9 项表头；表五每页带 3 项表头与 8 个姓名，多页时全部页一起带走；表六每页带 4 项表头（续页通常只有 3 项）与整列合一的备注，多页时全部页一起带走。正文不会随文件进来，导入后按当前项目的表一/表二重新推导。
- 表G 每页带 `meta`（4 项表头）、`role`（`start` / `cont`）、`source`（来源快照，只在开始页有值）与 11 行 `rows`，多页时全部页一起带走，跨页导线的页序与角色原样往返；导入后原样放回，不按当前项目的表一重算，也不改变表一、表六。旧文件没有 `role` 时全部按开始页载入，不会自动合并成一条导线。`settings.traverseCalc`（顺/逆时针、fβ 系数、K 分母、连接角方向、起算坐标与提示状态）随表G 设置一起导入导出，导入会整体替换。
- 表二的单表文件会带上每页的「归属」标签（`owner: {person, leg}`），导入后表五仍按这些标签取数；不带标签的旧文件导入后按页块规则汇总。
- 因此，把表四（或表六）文件导入到一个表一为空的项目时，表头会变，但正文仍然空白；这是预期行为。表G 文件不受表一影响，导入后各行照原样显示，跨页的导线也按原页序继续算。
- 表四固定一页；表五、表六、表G 可多页（上限 100）。表五导入会整体替换当前项目的表五页数与姓名，表六导入会整体替换表六的全部页，表G 导入会整体替换表G 的全部页（含页角色与来源记录），但不改变表一的页数或表二的数据。
- 表六的路线档（`closed`）、较差公式（`sideFormula`）与两个较差系数（`sideLimit` / `sideLinear`）、闭合差系数（`closureLimit`）随表六设置一起导入导出，正文仍按当前项目的表一重算。导入会整体替换 `settings.trigSummary`；起算坐标已不属表六（在表G 的 `settings.traverseCalc` 里）。

### 联立期间的限制

联立开启时，表一与表三存在映射写入关系，单独导入任一张都会绕过映射，因此直接拒绝，不弹确认框：

> 联立中：表一和表三由映射联动，不能单独导入。请先解除联立；表二可直接导入。

表二、表四、表五、表六、表G 不参与联立，联立期间可以正常单表导入（表G 允许单表导入）。要恢复表一/表三，先「解除联立」，导入后再重新开启。

## 旧版兼容

- 单表文件只给当前软件用；旧 `正式版` 不识别，也不应该识别。
- 需要给旧 `正式版` 的文件，用「导出整个项目（七表）」或项目菜单的「导出当前项目（七表 JSON）」，得到旧 v1 信封。旧版会读三张记录表，忽略表四/表五/表六与表G 的页键。表二读数在本软件里按米存，导出 v1 文件时八个读数会换回 mm 整数，旧版照样算得出视距与高差；单表文件只给本软件用，保持米。
- 设置里的 `limitsRev` 是本软件的限差版本标记，旧 `正式版` 只读它认识的 `c2Limit`/`indexLimit`/`halfDiffLimit`/`angle.limit`，会忽略这个键。老项目或旧版导出的 v1 文件没有 `limitsRev` 且仍是旧默认值（60″/60″/20″、40″）时，载入会换成课程口径（12″/25″/20″、20″）；用户改过的值不动。
- 旧版导入当前项目的 v1 文件仍会整体替换三张记录表；当前软件导入旧三表文件时会补四张空白页（表四/表五/表六/表G），行为与本功能之前一致。

## 文件命名

- 单表：`测量学七表-<项目名>-<表一|表二|表三|表四|表五|表六|表G>-<时间戳>.json`
- 整个项目：`测量学七表-<项目名>-<时间戳>.json`
- 全部项目：`测量学局劲-全部项目-<时间戳>.json`

项目名会净化 Windows 非法字符并截断；实际保存路径以系统对话框或 toast 为准。

## 手工验收

1. 表一填一格 → 顶栏「导出」→ 用文本编辑器打开文件，确认 `kind: "table"`、`table: "traverse"`，其余六表各是一张空白页。
2. 表二填不同的值 → 导入刚才导出的表一文件 → 确认后表二的值仍在，表一被替换。
3. 导出表四 → 改表头后导入 → 表一/表二/表三数据不动，表四表头被替换、正文仍按表一显示。
4. 表G 带入 ≥12 站（自动两页）→ 导出 → 在另一个项目导入 → 两页、页角色、行与来源记录原样回来，分页标签仍写「第 1–11 站 / 第 12–N 站」，`settings.traverseCalc` 一并替换。
5. 「导出整个项目（七表）」→ 导入 → 七表都回来。
6. 开启联立 → 导入表一/表三的单表文件被拒；导入表二、表G 允许。
7. 项目菜单「导出当前项目（七表 JSON）」→ 旧 `正式版` 可正常导入三张记录表。
