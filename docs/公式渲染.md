# 公式渲染：助手消息中的 KaTeX

> 2026-11-04 · AI 助手 · 只改前端显示层

## 范围

- 只有**助手消息**走公式渲染；用户消息保持纯文本，`$x$` 原样显示。
- 行内公式与块级公式都支持，块级公式可跨行；同一段落里的中文、表格、加粗、代码与公式可以混排。
- 不引入 MathJax，不联网加载任何资源；KaTeX 随应用打包。

## 定界与边界

| 写法 | 结果 |
|---|---|
| `$a^2+b^2=c^2$` | 行内公式 |
| `$$\frac{a}{b}$$`（独占一行） | 块级公式，居中 |
| `$$\n...\n$$` | 跨行块级公式 |
| `$$x$$ tail` | 不渲染，按原文显示 |
| `$$\n\frac{a}{b}`（未闭合） | 流式期间按原文显示；闭合到齐后再渲染 |
| `\$5` | 转义，按 `$5` 显示 |
| `$5 和 $10` | 货币，不当作公式 |
| `$x$2` | 结尾 `$` 后紧跟数字，不当作公式 |
| `` `$x$` `` | 行内代码，保持原文 |
| 围栏代码块里的 `$...$` | 原样显示，不渲染 |

行内公式的三条判定：

1. 开头的 `$` 后面不能是空白，也不能紧跟另一个 `$`；
2. 收尾的 `$` 前面必须是非空白，内容不能为空；
3. 收尾的 `$` 后面不能紧跟数字（避免把「$5 和 $10」误判成公式）。

块级公式的收尾 `$$` 必须是该行最后一个非空白内容；不满足就按原文显示。这条规则让「$$...$$ 后面还有话」不会把后半句吞进公式。

## 代码优先

源码里先做两层遮罩，再做公式提取：

1. 围栏代码块（```` ``` ```` / `~~~`）整段替换成占位符，未闭合的围栏一直遮到文末，与原有 Markdown 渲染的边界一致；
2. 行内代码 `` `...` `` 替换成占位符，保留原始反引号，恢复后仍交给行内代码渲染。

遮罩完成后才扫描 `$`，所以代码里的 `$` 永远不会被当作公式。公式内容本身若含占位符（例如公式里写了反引号），则放弃渲染，按原文显示。

## 渲染管线

`render(markdown, { math: true })` 的顺序：

```
原文 → 遮罩代码 → 提取公式（换成 \u0000M0\u0000…）
     → 恢复代码占位符 → escapeHtml → 原有块级/行内 Markdown
     → 把 M 占位符换回 KaTeX HTML（失败则换回转义后的原文）
```

- 占位符用 NUL 分隔，不会与正文冲突；先提取再转义，公式里的 `<`、`&` 不会被 HTML 转义破坏。
- 只有助手渲染点传 `math: true`；`MARKDOWN.render(text)` 的默认行为不变，用户消息和其他调用方仍按纯文本/普通 Markdown 处理。
- 解析失败时不抛异常、不显示红色 `katex-error`：`renderToString` 失败或输出含 `katex-error` 时，回退为转义后的原始公式文本。

## 安全

- `trust: false`：`\href`、`\url`、`\includegraphics` 等受信任命令不生成链接/资源；原始 HTML 也不会穿透。
- `throwOnError: false`：坏公式不中断整条消息。
- `strict: false`：不对非标准写法发严苛警告，避免中文排版里常见的兼容写法被判死。
- KaTeX 只输出 HTML/CSS，不执行脚本；公式内容不能成为事件处理器。

## 流式与缓存

- 只渲染**已闭合**的公式；流式过程中未闭合的 `$$` 保持原文，收尾 `$$` 到达后下一次绘制才变成公式。这样不会出现半截公式乱跳。
- 渲染结果按 `"D\u0000" + tex`（块级）或 `"I\u0000" + tex`（行内）缓存在 `Map` 里；同一公式在流式重绘中只排版一次。
- 缓存上限 500 条，超过就整体清空；失败结果（`null`）也缓存，避免坏公式反复触发异常。
- **顺手修复**：流式绘制的行选择器原来只按 `[data-nid]` 查，用户行与助手行共用同一个 nid，先命中的是用户行，导致无思考内容的回答在生成期间看不到正文、直到收尾才一次性出现。现在锁定 `.agent-row.is-assistant[data-nid=...]`，流式正文（含公式）即时可见。

## 资源与样式

- `web/assets/vendor/katex/`：官方 KaTeX **0.19.0**，23 个文件：`katex.min.js`（272,868 B）、`katex.min.css`（24,793 B）、20 个 woff2 字体（约 296 KB）、`LICENSE`（MIT，1,107 B）。
- 用 **UMD** `katex.min.js`，不用 ESM `katex.mjs`：浏览器版可能以 `file://` 打开，模块脚本会被 CORS 拦住；经典脚本没有这个问题。`index.html` 里先加载 KaTeX，再加载 `markdown.js`。
- 资源全部本地打包，`csp: null` 下不需要额外白名单；Tauri 构建时随 `web/` 一起嵌入。
- CSS：`.agent-msg-text .katex { font-size: 1.06em; }`；块级公式 `margin: 10px 0; padding: 2px 0 3px; max-width: 100%; overflow-x: auto; overflow-y: hidden;`，内部 `.katex` 不换行。超宽公式在消息列内横向滚动，不把聊天列撑宽；暗色下颜色继承 `currentColor`，不需要单独换色。
- 420px 最窄列下，超宽块级公式出现内部横向滚动条，页面本身不横向溢出。

## 明确不做

- 用户消息里的公式渲染（保持纯文本，避免复制/编辑时看到渲染结果）。
- 公式编号、引用、自动换行、点击放大、复制 LaTeX 源码按钮。
- mhchem/化学式、自定义宏、`\newcommand`、外部 `\input`。
- 导出带公式的 PDF/图片（助手消息本身没有导出入口）。
- 用 MathJax 或在线 CDN；不引入第二套数学排版。
