# 主题与外观

界面提供三种外观：**白**、**黑**、**跟随系统**。默认白；白色主题是中性白 / 石墨灰 / 强调蓝，与 AI 助手页同一套色板。

## 入口

任意一张表的「选项」抽屉 →「外观 · 全局」。七张表共用这一段，但选的是同一个全局偏好；切换表格或切换项目都不会变。

- 白：中性白界面 —— 纸面、顶栏、抽屉、弹窗、项目菜单纯白，标题栏/底栏/检查面板软灰，正文石墨灰，强调蓝。
- 黑：外壳、抽屉、检查面板、联立页与表格纸面一起转深，印刷线与表格文字改浅色。
- 跟随系统：读取 Windows 的「应用模式」深/浅色，系统切换时界面实时跟着变。

## 白色主题：中性白

白色主题不再用暖纸米黄，改用中性白 / 石墨灰 / 强调蓝：

- 面：表格纸、顶栏、抽屉、弹窗、项目菜单、输入框纯白 `#ffffff`；标题栏、底栏、检查面板、分组头 `#f9fafb`；控件底 `#f3f4f6`。
- 线：分割线 `#e5e7eb`，强线 `#d1d5db`，内部分隔 `#eef0f3`。
- 字：正文 `#111827`，次级 `#374151`，弱化 `#6b7280`，占位/装饰 `#9ca3af`。
- 交互：控件悬浮 `#f6f7f9`，表格格悬浮 `#eef2f7`，有值格 `#f8fafc`，联立只读格 `#eff6ff`；强调蓝 `#2563eb`、hover `#1d4ed8`、浅蓝 `#eaf2fe`。
- 误差四色不变：白 ≤1×、绿 1–2×、黄 2–3×、红 >3×，只把底色与字色换成中性绿 / 琥珀 / 红。
- 暗色规则原样保留，只在暗色块补新 token 的暗色值；打印仍是白纸黑字。

## 存储与首帧

偏好存在 WebView 的 localStorage：

```
survey-jujin.theme = "light" | "dark" | "system"
```

这是**本机界面偏好**，不是项目数据：

- 不写入 `store.json`，不进入项目导出/单表导出/全部项目导出；
- 不参与备份与恢复；
- 桌面版重装或清除站点数据后回到默认白；
- 换项目、导入项目、恢复备份都不影响主题。

`web/assets/theme.js` 在 `<head>` 里同步加载，先于样式表和页面内容设置 `data-theme`，所以深色启动不会先闪一下白屏。它还会在 `<html>` 上写 `data-theme-pref`（用户选择）和 `color-scheme`，让滚动条、原生控件跟着深浅色走。

主题模块载入失败时，软件仍可正常使用，只是固定白色；选项里会显示「主题模块未载入」。

## 切换动画

在选项里点「白 / 黑 / 跟随系统」时，新旧界面用约 0.26 秒的交叉淡化过渡：旧配色淡出、新配色同时淡入。

- 用 Chromium 的 View Transition（Tauri 的 WebView2 与开发用 Edge 都支持）；主题切换与抽屉重渲染都在同一次更新里完成，所以选中态和配色一起过渡。
- 旧内核没有 `document.startViewTransition` 时，退化为整屏覆盖层：先淡到舞台底色，在完全看不见时换主题，再淡出露出新界面（约 0.13 秒 + 0.19 秒）。
- Windows 关闭了动画效果（`prefers-reduced-motion: reduce`）时不做动画，立即切换。
- 「跟随系统」下系统深浅色变化也走同一个动画；如果新旧配色其实相同（例如系统本来就是浅色时从「白」切到「跟随系统」），不空转动画。
- 动画只影响屏幕显示；打印始终白纸黑字，覆盖层在打印时强制隐藏。

## 深色主题的范围

- 外壳：标题栏、顶栏、项目菜单、底栏、检查面板、选项抽屉、模态框、提示条。
- 页面：AI 助手页、联立映射页、表格舞台。
- 表格：纸面 `#1c2329`，印刷文字 `#e2e7e9`，印刷线 `#9aa6ac`；输入值、DMS 组、计算格都继承浅色文字。
- 交互：悬浮格、聚焦环、超限/缺项描边、联立只读格的冷色底都换成深色版本。
- 主按钮使用深蓝填充配浅字，避免深色界面里出现大片亮蓝色。
- 表二底栏的「归属」胶囊与归属弹层同样转深：胶囊深灰底 + 暖色字，弹层 `#171e23` 底、`#333d45` 边；弹层里选中的段按钮用浅蓝底配**深墨字**（深色下 `--accent-2` 是浅蓝，白字会看不清）。

AI 助手消息区的滚动条也跟随主题：宽度固定 9px、槽位常驻，只有滚动时才显色。亮色 `--agent-scroll-thumb: rgba(17,24,39,.28)`、hover `.44`；暗色 `rgba(231,227,217,.26)`、hover `.40`。停手约 0.9 秒淡出，不改变列宽。

右侧导航轨同样跟随主题：横条静止色用 `--agent-rail-rgb` 配透明度（亮色 `17, 24, 39`，暗色 `231, 227, 217`），驻场琥珀为 `--agent-rail-pin`（亮 `#f59e0b`、暗 `#e0b166`）；当前可见轮、分支点继续用强调蓝，暗色浮窗卡使用暗色 `--agent-bg`。详见 `docs/导航轨.md`。

打印不跟随主题：所有深色规则都在 `@media screen` 内，打印样式仍强制白纸、黑字、原印刷线。也就是说，黑主题下点「打印」，输出的仍是原来的白底记录表。

## 跟随系统的边界

浏览器的 `prefers-color-scheme` 只能读到 Windows 的**应用深浅色模式**（设置 → 个性化 → 颜色 → 选择默认应用模式）。它读不到：

- Windows「夜间模式 / 护眼模式」的暖色滤镜——那是显示层滤镜，网页内容无法感知，也不需要感知；
- 显示器自身的低蓝光/阅读模式。

因此「跟随系统」只保证和应用模式同步；如果只是想让白底不刺眼，直接开 Windows 护眼模式即可，主题仍可选白。

## 代码

- `web/assets/theme.js`：偏好读取、系统解析、应用与监听；`setPreferenceAnimated()` 负责 View Transition / 覆盖层降级与减少动画判断，纯逻辑 + DOM 无关的测试接口。
- `web/assets/app.js`：`addAppearanceSection()` 渲染「外观」分段控件，点选走 `setPreferenceAnimated()`，抽屉重渲染放在同一次更新回调里。
- `web/assets/style.css`：`:root` 的全局色板（`--ink/--line/--shell/--paper/--accent/--band-*` 等；白色主题即中性白，`--desk` 为舞台底色）；文件末尾 `@media screen { html[data-theme="dark"] ... }` 为全部深色覆盖；`::view-transition-old/new(root)` 控制淡化时长，`.theme-fade` 为降级覆盖层；打印块里的 `color-scheme: light !important` 保证打印预览不受深色影响。
- `tests/theme.test.js`：12 项偏好、解析与动画接口测试（Node 无 DOM 时动画接口同步落定）。
- `web/assets/agent.css`：Agent 消息区滚动条的亮/暗令牌与 `.is-scrolling` 显隐规则（详见 `docs/聊天列宽.md`）；导航轨的 `--agent-rail-rgb` / `--agent-rail-pin` 与浮窗暗色阴影（详见 `docs/导航轨.md`）。

## 手工验收

1. 打开任意表 →「选项」→「外观」，点「黑」：整个界面与表格纸面用约 0.26 秒交叉淡化转深，选项里的「黑」保持选中。
2. 关闭软件再启动：仍是黑，启动过程没有先闪白。
3. 点「跟随系统」，在 Windows 设置里切换应用模式深/浅，界面实时跟着变，并且也是淡入淡出。
4. 在 Windows 设置里关闭「动画效果」再切换主题：应立即切换，不再淡化。
5. 黑主题下打印预览：仍是白纸黑字，表格线与文字与白主题一致。
6. 切换项目、导出再导入项目：主题不变。
7. 点「白」恢复原样；清除站点数据后重新打开：回到白。
