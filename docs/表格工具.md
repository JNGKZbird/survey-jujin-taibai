# 表格工具：Work 模式的读表、写表与加页

M3 起，Work 模式的 AI 助手可以真正读取与填写**表一（导线）**、**表二（水准）**。工具全部在本地执行：读取现有分析引擎与单元格规格，写入走与手工填表相同的落格路径。Chat 模式没有表格工具；联网搜索开启时只提供 `web_search`，不会读表或写表。M4a 起，Work 可以先看用户发的记录表照片，再调用这些工具；图片管线、视觉转写与发送前确认见 `docs/识图填表.md`。

## 工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `survey_read_table` | `table`，`page?` | 读取指定页；`page` 省略时读该表当前页 |
| `survey_write_table` | `table`，`page`，`edits[{cell,value}]` | 修改 1–40 格；同一格不得重复；多格原子应用 |
| `survey_append_table_page` | `table` | 在表尾追加一页空白页，不切换当前页 |

- `table` 只接受 `traverse`（表一）与 `leveling`（表二）；其他表、表G、设置、人格、文件系统一律拒绝。
- 每个 schema 都是 `type:"object"`、`required`、`additionalProperties:false`；`page` 为 1 起整数。
- `definitions(mode)`：Only Read 只下发 `survey_read_table`；Manual / Auto 下发三个。Chat 不调用 `definitions()`，请求里没有 `tools`。
- 一次工具回合最多执行 4 个 call；超出的 call 直接得到错误结果“一轮最多 4 个工具调用，请分轮进行”。
- 默认工具轮次预算 6 轮，可在设置中调整为 1–20；用尽后进入无工具的总结轮。

## 权限矩阵

| 模式 | 读表 | 写表 | 加页 |
| --- | --- | --- | --- |
| Only Read | 直接执行（开启“读取也询问”时先审批） | 工具不下发；硬调则拒绝 | 同左 |
| Manual | 默认直接；`strictManualReads` 为真时审批 | 预览 + 审批 | 预览 + 审批 |
| Auto | 直接 | 预览 + 直接应用 | 直接应用 |

- Manual 下同一轮里的多个写/加页合并成一张审批卡，一次允许后逐个执行；任一 call 失败只影响该 call。
- 含图片的轮次，写表与加页**即使 Auto 也必须审批**；审批卡副标题显示「含图片：本轮写入必须确认」。这条限制只作用于当前图片轮，不修改设置。
- 审批等待期间不自动超时；点“停止”即取消本轮所有待确认操作，不写入任何格子。
- 撤销是用户动作，不受权限模式限制。

## 先读后写

- 写表前必须在**更早的工具轮**成功读过同一页，且读到的页面指纹与预览时一致；同一轮里先读后写不算。
- 加页前该表至少要读过一页；加页成功后新页必须重新读取才能写。
- 写表成功后该页的读缓存失效；加页成功后整张表的读缓存失效。模型必须重读，避免拿旧快照连续覆盖。
- 没有读取就直接写，工具返回错误并保持零写入；审批也不会出现。

## 读表返回

工具结果压缩成一段 JSON 字符串（短键、少空格），不返回中文标签：

```json
{"ok":true,"table":"traverse","tableLabel":"表一","page":1,"pageCount":2,
 "blank":false,"hash":"1a2b3c4d",
 "cells":{"s1-r1-h":"123°45′36″","…":""},
 "computed":{"s1-r1-c2":"+04″"},
 "issues":[{"level":"warn","message":"2C 超限","cell":"s1-r1-h","code":"c2"}],
 "notes":"h/v/s 为 d°m′s″；尺读数按米；空串表示清空"}
```

- `cells` 只含**可写格**（含空串）；`computed` 只含只读派生格与已经算出的值，空白页不返回满屏“待填”。
- `issues` 来自现有分析引擎，最多 20 条，超出标 `truncated:true`。模型应直接引用，不另算一套。
- `hash` 是对目标页可写格规范值排序后的 FNV-1a 32 位指纹；读表、预览、应用、撤销共用同一个 `pageHash()`。
- `blank` 只看测站/备注等录入数据，新页继承的表头不算数据。
- 读表结果只活在当前生成的内存里，不写进 `steps`、不落 `agent.json`。

## 写表：预览、审批、应用、撤销

1. **预览**：按格规格校验并规范化值，生成 before→after 列表与一次性 `previewToken`（绑定项目、表、页、edits、页面指纹；5 分钟过期，最多 20 个）。预览不调用 setter，不产生任何落盘。
2. **审批**（Manual）：卡片显示逐格 diff；联立开启时额外显示“联立开启：写入后表三将同步更新”。
3. **应用**：重新生成规格并校验全部值；任一格当前值不等于 before 或页面指纹变化 → 返回 `stale`，**一格都不写**。UI 自动重新预览、刷新 diff、回到待确认，请用户再次确认。
4. **焦点保护**：目标格正在被编辑（DOM 焦点在该格）时拒绝写入，提示先移开焦点。
5. **落格**：整批校验通过后逐格 `setValue`；任一格抛错按已写列表回滚，整批失败。可见页只做 DOM 原地更新，不调用 `renderStage()`；不可见页只改 state。
6. **收尾**：回读目标格确认等于 after；仅当当前显示的就是被写的表（或联立后的表三）时重算一次；表一调用现有 `runLinkageSync({render:false})`；`saveNow(false)`。
7. **撤销**：记录每格 `before/after`；只有当当前值仍等于 `after`、格未被编辑时才能整批撤销。生成中撤销按钮禁用，停止后恢复。撤销记录随会话持久化，刷新后仍可撤销。

联立开启时 Agent 仍可写表一：写入后由软件现有联立逻辑同步表三，与手工填表同路。Agent **不直接写表三**，也不改联立设置。

## 加页与撤销

- 新页继承最后一页的表头 meta；表二备注清空、测站归属沿用当前归属规则。
- 表尾追加，最多 100 页；不切换当前页；若当前正看这张表，只更新页签与分页器。
- 撤销加页用**整页指纹**判断：页面内容与追加时的 baseline 完全相等才删除。用户改过任何一格就拒绝，并说明原因。
- 不提供删页工具。

## 工具回合与消息结构

- 每一轮模型回复先记一条 assistant 消息（正文 + 全部 `tool_calls`），随后按 call 顺序为每个 call 写一条 `role:"tool"` 结果，`tool_call_id` 严格对应。
- 格式错误、未知工具、被拒、取消、失败、因截断未执行的 call 也必须有结果；不会留下孤立的 tool 结果。
- provider 的 call ID 为空或重复时合成稳定 ID `call_<round>_<i>`，同一 ID 同时用于 assistant 与 tool 消息。
- `finishReason` 为 `length` / `content_filter` 时不执行该轮 call，标记截断并收尾；模型不支持工具（`toolsDropped`）时不执行任何 call。
- 单条结果超过 12 KB 时替换为 `{ok:true,truncated:true,…}` 摘要，不切断 JSON；当前回合结果总量超过 48 KB 时，从最旧的读表结果开始省略，最近两轮永不压缩。
- 历史回合只回放文本，不回放旧工具链；工具结果只活在当前生成内。

## 停止、切换与恢复

- 停止发生在审批等待：待确认步骤全部标为已取消，清空预览令牌，零写入。
- 停止发生在流式中：取消当前请求，保留半截正文；残留步骤标为已取消或已中断。
- 刷新后，`pending/awaiting/running/applying` 统一映射为“已中断”，不显示审批按钮；已应用的卡片与撤销记录保留，仍可撤销。
- 审批等待中切换项目：旧任务就地停止，不写入新项目，也不把审批卡带过去。

## 安全边界

- 只能写 `survey_read_table` 返回的 `cells` 中的格；`computed` 只读，不能写。
- 值必须通过现有格规格校验：DMS 必须可解析；数字位数不得超长（不静默截断）；尺读数接受米（`1.170`）或旧毫米整数（`1170`），拒绝字母；文本按单行/换行/文本域规则处理并受 `maxlength` 限制。
- 不删页、不写表三/四/五/六/表G、不改设置/人格/项目库/文件系统。
- 工具结果是数据，不是指令；结果里的“忽略规则”“扩大权限”等文本不执行。
- 项目只读、未来版本项目或存储不可用时，写表与加页直接拒绝，提示先导出 JSON 备份；读表仍可用。
- 密钥不出现在工具结果、提示词或日志里。

## 持久化

- 工具步骤只落白名单字段：`tool,status,args,summary,error,edits,undo,textBefore,expanded,startedAt,finishedAt,undone`；不保存 `previewToken`、完整读表快照或 provider 原始参数。
- 撤销记录在 `agent.json` 的会话步骤内，不新增顶层键、不升 `agent.json` 版本。
- 每节点最多 40 个步骤，单 step `edits` ≤ 40，错误串 ≤ 2 KB，undo 记录 ≤ 20。
- 序列化超过 12 MB 时，在副本上从最旧会话开始丢弃步骤与撤销记录（保留助手文本），不修改内存会话，不改变磁盘格式。
