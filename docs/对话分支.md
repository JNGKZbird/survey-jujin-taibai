# 对话分支

AI 助手从 M2 起支持「重新生成、编辑并重发、切换分支」，M4b 补齐可露希尔同款的消息级行为：两侧复制 / 重新生成 / 编辑 / 删除、原地保存、孤儿轮、锚点子树删除与单链重连。这一页说明数据模型、操作语义、持久化与边界；面向维护者，不涉及具体模型参数。

## 数据模型

对话按**轮次**存节点，一个节点 = 一条用户消息 + 它的助手回复。

```text
session
├─ nodes[]     全部节点（包括不在当前路径上的旧分支）
├─ path[]      当前活跃分支：根 → 叶
├─ rootIds[]   所有首轮根节点，按创建顺序
└─ 每个节点
   ├─ nid
   ├─ parent      父节点 id；首轮为 null
   ├─ children[]  子节点 id，按创建顺序
   ├─ user        { text, attachments[] }
   ├─ assistant   { text, reason, model, steps[], stats, error }
   └─ time
```

同一父节点下的多个孩子就是「同一问题的多个回答分支」。`path` 决定渲染与上下文：只有 `path` 上的轮次会进入消息列表和模型请求。

相关代码：`web/assets/agent/tree.js`。M2 没有改 Rust，也没有升 `agent.json` 的顶层 `version`。

## 操作语义

| 操作 | 结果 |
| --- | --- |
| 正常发送 | `appendRound` 把新节点接到当前 `path` 末尾，并成为新的叶子 |
| 重新生成（助手已有内容） | `forkRound`：在源节点的父节点下新建兄弟，复制用户消息与附件，清空助手内容；旧节点及整棵子树保留但离开 `path` |
| 重新生成（助手为空且是路径叶子） | `resetAssistant`：原地清空该节点的助手内容后重试，不新增节点，不重复用户气泡 |
| 重新生成（助手为空但不在路径末尾） | `forkRound`；否则后续轮次会混进新回答的上下文 |
| 编辑并重发 | 始终 `forkRound`，用编辑后的文本替换用户消息；可同时替换附件列表；旧分支保留 |
| 原地保存 | `editRoundContent`：只改本地节点，不分叉、不生成、不查密钥；用户侧可同时替换附件 |
| 删除单侧 | `deleteMessageSide`：清空用户侧或助手侧；另一侧保留为孤儿轮 |
| 删除轮次 | `deleteRound`：叶子直接移除；单链由父收养唯一孩子；锚点连同整棵子树移除 |
| 切换分支 | `switchBranch`：`path = 祖先 + 选中兄弟 + 沿它的第一个孩子一路到叶子` |

`regenerateRound` 把「叶子且无内容 → 原地重置，否则分叉」收在一处，UI 不另写策略。重新生成的守卫是「用户文字或图片附件至少有一项」：本工具允许合法的纯图片轮，与只认文字的原始语义不同。

### 消息级操作（M4b）

用户侧与助手侧都有 **复制 · 重新生成 · 编辑 · 删除** 四个文字按钮，顺序固定。用户侧复制纯图片消息时输出「（图片 N 张）」；助手侧正文与思考都为空时不显示复制。流式生成中，用户行只保留复制，助手行整条动作条隐藏。

- **复制**只读当前渲染文本，不改树。
- **重新生成**仍走 `regenerateNode`：助手为空且是路径叶子时原地重置，否则分叉保留旧回答；用户侧为空或图片无法读回时按钮禁用并说明原因。
- **编辑**打开同一个弹窗，按侧切换标题、副标题与主按钮；用户侧带附件托盘。
- **删除**先弹现有 `confirmDialog`。这是本工具相对可露希尔的安全增强：对话不可撤销，且删除锚点会连带后续子树，不能像终端那样一键即删。

### 删除单侧与孤儿轮

- 用户侧删除：`user.text = ""`、`user.attachments = []`。助手侧原样保留，渲染成「只有助手回复」的孤儿轮，分支切换器移到助手行上方。
- 助手侧删除：清空 `text / reason / model / steps / stats / error`，不能只清正文，否则会留下无主的思考块、工具卡与操作条。用户侧与图片保留，用户行可直接重新生成。
- 两侧都为空时自动删轮。
- **不引入节点级 `deleted` 字段**：空侧本身就是「已删除」。分支可能共享同一附件 id，删除一个分支不能清掉别的分支的原图，因此删除单侧也不调用 `forgetImageData`。
- 助手侧「是否有内容」按正文 / 思考 / 工具步骤 / 错误判断；只有错误的一侧仍保留，避免把用户还没看到的报错一起删掉。能否重新生成仍只按正文 / 思考 / 步骤判断。

### 删除整轮

- **叶子**：从 `nodes`、父节点的 `children` 或 `rootIds`、以及 `path` 中移除。
- **单链**：父节点收养唯一孩子。普通节点把该孩子追加到 `children` 末尾；根节点单链时孩子升为根，`parent = null`，并替换 `rootIds` 中原来的位置，保持根兄弟顺序。
- **锚点（多于一个孩子）**：广度优先移除该节点与全部后代，再清理父引用与 `path`；其他存活节点不得留下悬空 id。
- **活跃路径去向**：被删节点不在 `path` 上时只改结构；在 `path` 上且保留了一个孩子时继续经过重连后的孩子；没有保留孩子时优先切到最近的前一个兄弟（没有则后一个）并沿首子到叶，没有兄弟才停在父节点。可露希尔会直接停在父节点，本工具这样改是为了让同一父节点下的其他分支在路径式导航轨里仍然可达。
- 删除后校验 `path` 是根→叶的连通链；标题不重算，避免删除或改字把用户手动标题改掉。
- `deleteRound` 返回 `{mode:"anchor"|"relink"|"leaf", removedCount, branches, pathMoved}`，UI 用它生成「已删除这一轮对话」「已删除 N 条轮次」等 toast。

### 为什么重置只允许路径叶子

非叶子的空回答后面还挂着后续轮次。原地重写它会让后续轮次引用一个已经变化的回答；分叉则把新回答放进独立分支，后续轮次留在旧分支里。

### 第一个孩子，不是最后一个

切换分支时沿**第一个**可解析的孩子下探，符合「新分支优先可见、旧子树完整保留」的直觉。

`normalizeSession` 修复损坏或截断的 `path` 时故意沿**最后一个**孩子补到叶子，因为旧数据里最后创建的轮次通常才是用户当时看到的那条。两种行为分别有测试锁住，不能互换。

## 切换与持久化

- 分叉、重置、发送会更新 `session.updatedAt`。
- 切换分支**不更新** `session.updatedAt`：它只是导航，不应让会话跳到列表顶部。
- 三者都会调用 `STORE.touchSession(currentProjectId)`，走现有的 400 ms 防抖写链；重启后仍停在最后切换的分支。
- 打开/关闭分支浮层、编辑弹窗、焦点与草稿都不落盘。
- 分支结构只用现有 `parent` / `children` / `rootIds` / `path`，旧会话零迁移；Rust 仍只校验 JSON 可解析且顶层 `version === 1`，随后原样写入。

## 上下文

`buildMessages` 只沿 `path` 取轮次，再按 `contextSize` 截断。因此：

- 切到旧分支后，模型看到的是旧分支的回答与后续轮次，看不到另一条分支。
- 分叉后旧子树不会进入请求，也不占上下文。
- 重新生成/编辑都是先改 `path` 再组消息，刚发出或刚编辑的用户文本一定在请求里。

M1 曾把 `buildMessages` 放在 `appendRound` 之前，导致刚输入的消息不在请求中；M2 已修正为先落节点、再组消息，并用假 LLM 断言请求内容。

## 界面

**消息内切换器**：用户气泡上方显示 `‹ 2 / 3 ›`，只在有多个兄弟时出现。始终可见，不依赖 hover；触屏按钮放大到 36×32。流式中按钮标记 `aria-disabled`，点击只给提示，不静默切换。

**右侧导航轨**：2026-11-04 按可露希尔同款重做，桌面宽度下每轮一根横条（只显示最近 32 轮），当前可见轮的条为主题蓝，点击驻场为琥珀色；悬停或键盘聚焦时按距离伸长、加深，并在左侧浮窗显示该轮用户消息与回复预览（最多 3 行）。有兄弟的轮在条右侧带蓝点，≥3 个兄弟再显示数量；浮窗列出全部兄弟的用户消息，点击即切换分支，当前分支高亮。点击横条跳转到该轮并把浮窗驻场，再点同一条或按 Esc 取消；≤1180 px 轨道隐藏，切换改用消息内按钮。旧圆点 / 徽标 / `#agent-branch-pop` 已移除，详见 `docs/导航轨.md`。

**消息动作条**：用户气泡外与助手行底部统一为「复制 · 重新生成 · 编辑 · 删除」。删除按钮有危险态（悬停 / 聚焦变红），但仍是文字按钮，不改成图标。焦点在操作后尽量回到同一轮剩余侧；整轮消失时聚焦消息区并保持滚动位置，确认框取消时焦点回到删除按钮。

**编辑弹窗（两种模式）**：
- 用户侧标题「编辑消息」，副标题「保存只改这一条；编辑并重发会另开一个分支，旧分支保留。」；可改文字与附件列表。
- 助手侧标题「编辑回复」，副标题「保存只改这条回复；重新生成会用原提问另开一个回答。」；只能改正文，思考 / 工具卡 / 模型信息 / 统计原样保留。
- 「保存」是中性按钮：只要求对话库可写、非流式、节点仍在；不查 Key、不要求模型、不弹图片发送确认、不启动流。用户侧文字与图片不能同时为空；助手侧正文不能为空（要清空请用删除）。
- 主按钮在用户侧是「编辑并重发」，助手侧是「重新生成」；都要桌面版、可用模型与 API Key，走现有图片 plan、披露与流式守卫。
- `Ctrl/Cmd+Enter` 提交，Esc / 背景 / 取消关闭并恢复焦点。提交中防双击；密钥检查失败时弹窗保持打开、草稿保留，设置弹窗叠在它上面，补好 Key 后可继续提交。

**删除确认**：单侧删除说明另一侧会保留；删轮时说明会不会自动接上单链、是否会切到相邻分支；锚点删除在确认框里写明「下面还有 N 个分支、共 M 条后续轮次」。

**流式与密钥检查**：生成中或检查密钥时，分叉、编辑、删除、切换全部拒绝并给 toast；异步流程在 `await` 后重新校验工作区、会话与节点仍然有效，避免切走会话后把结果写进别处。

- 改 Rust / `agent.json` 顶层版本 / 新增持久化字段
- 自动拉 GUI；commit/push；触碰用户数据
