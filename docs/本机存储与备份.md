# 本机存储与备份

## 文件位置

桌面版（Tauri）：

- 项目库：`%APPDATA%\com.jngkzbird.survey-jujin\store.json`
- 备份目录：`%APPDATA%\com.jngkzbird.survey-jujin\backups\`
- 损坏隔离：`%APPDATA%\com.jngkzbird.survey-jujin\store.corrupt-YYYYMMDD-HHMMSS.json`

界面里的实际路径以「选项 → 数据 → 项目库 / 备份目录」和「项目菜单 → 打开备份目录」为准；路径由 `get_paths` 从 Tauri 的应用数据目录读出，不在代码里写死。

浏览器开发版仍用 localStorage 键 `survey-jujin.dev.v1`，没有本机文件与自动备份；换浏览器或清站点数据前请导出 JSON。

## 对话库（agent.json）

桌面版的 AI 助手对话存在 `%APPDATA%\com.jngkzbird.survey-jujin\agent.json`，同目录保留一份 `agent.json.bak`；它是独立文件，不写进项目库 `store.json`，项目导出也不含对话。

M2 的分支结构完全复用现有字段：每轮一个节点，`parent` / `children` 记录兄弟与父子关系，`rootIds` 记录首轮根，会话的 `path` 记录当前活跃分支。**没有升版本，旧会话零迁移。** Rust 侧仍只校验 JSON 可解析且顶层 `version === 1`，随后逐字节写入；分叉/编辑/切换后的保存走同一条 400 ms 防抖写链。

Chat / Work 模式保存在会话的 `agentMode`（`"chat"` / `"work"`）与会话库设置的 `agentMode` 中，默认 `work`。旧会话与旧设置缺这个字段或值非法时按 `work` 处理；新会话继承最后一次选择的模式。它同样不升版本，Rust 不解析内层字段。

M3 的表格工具步骤也只写进现有会话节点：工具名、状态、参数、diff 摘要、错误、撤销记录与 `textBefore` 走白名单，**不新增 `agent.json` 顶层键、不升版本**。一次性预览令牌、完整读表快照与 provider 原始参数不落盘；刷新后未完成的步骤显示为“已中断”，已应用的步骤保留可用的撤销记录。每节点最多 40 个步骤，单 step 的 `edits` 最多 40 条、undo 最多 20 条；序列化估算超过上限时，会在**副本**上从最旧会话开始丢弃步骤与撤销记录（保留助手文本），不改内存会话与磁盘格式。

容量上限按存储模式分开计算：原生 `agent.json` 按 UTF-8 字节估算，上限 **12 MB**；浏览器 localStorage 受约 5 MiB 的站点配额限制，按 UTF-16（`text.length * 2`）计量，上限 **4.5 MiB**。两种模式各用各的阈值，避免 localStorage 因中文与 base64 的 UTF-16 膨胀而先超配额。

M4a/M4b 的图片附件挂在用户消息的 `attachments` 上，只保存 `id / kind / mime / name / w / h / bytes / thumb / transcript` 白名单字段；完整图片的 data URL、本地路径、`stored` 标记都不写入 `agent.json`。原生模式下 `agent.json` 会保存小缩略图与转写文字，`agent.json.bak` 作为上一版副本也可能含缩略图；**两者都没有加密**。浏览器/localStorage 模式在序列化时剥离缩略图，只保留尺寸、名称与转写。超过对应模式的上限时，先从最旧会话丢弃缩略图，再丢弃工具卡与撤销记录。`visionModel`、`imageSupport`、`imageDisclosureAcks` 存在既有 `settings` 内，仍不升 `agent.json` 版本、不新增顶层键；图片不写项目库 `store.json`，不进项目备份与项目导出。详见 `docs/识图填表.md`。

M5 的联网搜索同样只写现有字段：搜索开关在 `settings.searchEnabled`（旧设置缺省视为开启），搜索步骤是普通 `assistant.steps[]`，来源只保存 `results` 里的 `title / url / site / date`，最多 8 条；**摘要、网页正文、站点图标与 rerank 分数不落盘**，只在本次生成的内存 `job.rounds` 里。重开会话后来源卡片仍在，展开可点原始链接；旧搜索工具结果在上下文超限时压缩为前 2 条来源元数据并提示重新搜索。仍不升 `agent.json` 版本、不新增顶层键；不写项目库 `store.json`、项目备份或项目导出。详见 `docs/联网搜索.md`。

## 图片附件目录（attachments）

压缩后的完整发送图在 M4b 起落盘，目录为 `%APPDATA%\com.jngkzbird.survey-jujin\attachments\`，与 `agent.json` 同级；实际路径以「设置 → 关于 → 图片缓存」读取的索引为准。

- **文件名**：`<id>.<jpg|png|webp>`。写入端只接受小写 `^[a-z0-9_-]{1,64}$`，并拒绝 `con/prn/aux/nul/com1-9/lpt1-9` 等 Windows 保留名；读取端兼容三种扩展名。索引与清理只认这些名字，未知文件、子目录与符号链接一律不动。
- **内容**：发送前压缩后的完整图片（长边 ≤ 2048、JPEG、已去 EXIF），不是相机原始文件，也不是原扩展名文件。
- **上限**：单文件二进制 ≤ 2 MiB；目录总量 ≤ 512 MiB。超限拒绝新写入并提示去关于面板清理；不会自动删除仍被引用的图。
- **不加密**：Windows 当前用户可见，与 `agent.json` 相同。
- **写入**：发送不等待落盘，后台串行写；关窗握手会等待附件写链结清。单张失败不阻断本轮发送，流结束后 toast 提示。临时文件带 `.tmp-` 前缀，崩溃残留超过 10 分钟会在下次启动清理。
- **启动索引**：启动时先扫描目录得到 id 集合与用量，再进入聊天界面；`resolveImagePlan` 用同步的 `has(id)` 判断磁盘是否有图。索引里有、读盘失败的 id 进入负缓存并移出索引，`put` 成功会清除该 id。
- **清理**：
  - 「清理未引用图片」：先冲刷 `agent.json` 写链与附件写链，再删除没有被 `agent.json` 或 `agent.json.bak` 引用的识别文件。
  - 「删除全部原图」：二次确认后删除本目录识别出的附件与临时文件；缩略图与转写仍在 `agent.json`，本次运行的内存副本仍在，重启后查看器退回缩略图。
  - 删除整个会话、清空工作区对话后后台自动清理未引用文件，不阻塞 UI。
  - 保守跳过：`agent.json` 缺失、不可读、非法 JSON 或 `version !== 1` 时整次 prune 跳过；`.bak` 存在但不合法同样整次跳过。绝不按空引用集误删。
  - 浏览器/localStorage 模式不落盘，关于面板两个清理按钮禁用。

## 界面偏好

主题（白/黑/跟随系统）存在 WebView 的 localStorage 键 `survey-jujin.theme`。它只是本机显示偏好，不写入 `store.json`，不进入备份，也不随项目导出；重启后保留，清除站点数据或重装后回到默认白。

聊天列宽（AI 助手）存在 localStorage 键 `survey-jujin.agentColumnWidth`，是一个整数像素值（默认 760，最小 420）。同样只是本机显示偏好，不写项目库、不进备份、不随项目导出；换电脑或清除站点数据后回到默认宽度。详见 `docs/聊天列宽.md`。

## 写入方式

- 前端每次修改后约 380 ms 防抖，经 `platform.js` 串行调用 `save_store`。
- Rust 先在校验 `schemaVersion == 2` 且 `projects` 为非空对象数组后写入；不合法直接拒绝，不覆盖现有文件。
- 写入流程：同目录临时文件 `.store.json.tmp-<pid>` → `write_all` → `sync_all` → rename 覆盖 → 回读逐字节比对。rename 失败时保留原文件，只删除临时文件。
- 所有保存、备份、导入读取共用一把进程内互斥锁，避免并发写同一目录。

## 自动备份

文件名 `YYYYMMDD-HHMMSS.json`；同一秒冲突加 `-2`、`-3`；破坏性操作前加 `-force`。

写入条件：

1. 内容与最新一份备份不同。比较前递归删除所有 `updatedAt` 字段，所以只是时间戳变化不会产生新备份。
2. 普通保存：当天还没有备份，或距最新备份至少 10 分钟。
3. 强制备份：不受 10 分钟间隔限制，但仍要内容不同。

强制备份的触发点：导入（`import` / `import-all` / `import-table`）、删除项目（`delete-project`）、清空页面（`page-clear`）、删除表一页（`traverse-delete`）、开启联立（`enable`）、恢复自动映射（`auto`）等。`import-table` 是单表导入，备份的是导入前的完整项目，另外两表也在备份里。备份失败不会拦住操作，但状态栏会显示「· 备份未写入」并弹出提示。

清理规则（每次保存后执行）：

- 最近 20 份一定保留；
- 最近 14 天每天的第一份保留；
- 最近 14 天的强制备份保留；
- 其余删除。

因此连续输入不会写爆备份，也不会只剩最近 20 份而丢掉每日节点。

## 恢复

1. 打开备份目录，按时间挑一份 `YYYYMMDD-HHMMSS.json`。
2. 在软件里「导入 JSON」选择它。备份是 v2 全部项目信封，会按「导入全部项目」流程整体替换当前项目库。
3. 导入前软件会先对当前库再做一次强制备份；确认框会说明项目数与页数。

只想恢复单个项目时，可以先导入全部，再删除不需要的项目；或直接打开备份文件，取其中一个 `project.state` 走旧 v1 导入。

## 损坏与版本过高

- 文件不是 UTF-8、JSON 无法解析、`schemaVersion` 不是 2、`projects` 不是非空对象数组：原文件改名为 `store.corrupt-时间戳.json`，应用开空白库并提示。损坏文件不会被删除，可事后手工抢救。
- `schemaVersion > 2`：原文件原样保留，应用进入只读内存模式，状态栏提示「项目库版本过新（未写入本机）」。升级软件后重新打开即可；当前会话的改动不会写入，需要时先导出。
- 本机存储不可用（目录不可写、命令失败）：进入内存模式，不静默回退到 localStorage；每次保存失败都会提示导出 JSON。关窗时会要求确认。

## 关窗与单实例

- 关闭按钮或系统关闭都会先被 Rust 拦截，发出 `app://flush`；前端冲刷联立、清 timer、保存并等待项目库与图片附件两条写链全部结束，再调 `confirm_close` 放行。
- 保存失败：取消关闭，状态栏与 toast 提示先导出。
- 12 秒内前端没有回应（卡死或页面未加载）时兜底关闭，避免窗口关不掉。
- 单实例插件保证第二次启动只聚焦已有主窗口，不会出现两个进程写同一份 `store.json`。

## 导入导出的限制

- 原生对话框：`tauri-plugin-dialog`；导出原子写入，默认名做 Windows 非法字符净化并补 `.json`；禁止把导出内容直接覆盖到 `store.json`。判断前先规范化路径：解析 `..`、大小写、符号链接 / junction 与 8.3 短名，并按 Windows 规则忽略文件名末尾的点与空格；目标尚不存在时从最近的已存在目录逐级回退比较。
- 导入按 UTF-8 读取，v2 上限 32 MB，v1 上限 8 MB（前端再校验一次）；超限或非 UTF-8 直接拒绝。
- 浏览器回退仍是 Blob 下载与 `<input type="file">`，不弹系统对话框。

## 手工验收清单

1. 填写一格后直接点 X，重新启动，确认最后一次输入还在。
2. 「项目菜单 → 打开备份目录」，确认有新备份；连续快速输入一分钟，确认不会每秒生成文件。
3. 做一次「清空本页」或「导入」，确认备份目录多出一份 `-force` 备份。
4. 把 `store.json` 手工改坏一个字符再启动，确认原文件改名为 `store.corrupt-*.json`，软件开空白库且能继续用。
5. 导出一份当前项目，再导入旧 `正式版`，确认三表数据正常；导出全部项目后再导入，确认多个项目都回来。
6. 在某张表的界面「导出」，再导入该文件：确认只替换这张表，另外两表不动；导入前的完整项目能在备份目录找到。
7. 连点两次程序图标，确认只出现一个窗口。
8. 断开备份目录写权限（或把目录设为只读）后保存，确认主文件仍能写、状态栏提示「备份未写入」。
9. 发一张图后立刻关闭窗口，重开在查看器里看到完整压缩图；`attachments` 目录里出现对应 `<id>.jpg`。
10. 删除一个含图会话，再打开关于面板「清理未引用图片」，确认该会话的图被清掉、其他会话仍在用的图不受影响；「删除全部原图」后重启，查看器退回缩略图。
11. 在 Work 或 Chat 模式搜索一次，展开工具卡点来源链接确认走系统浏览器；关闭软件重开，来源卡片仍在且只有标题 / 站点 / 日期，没有摘要正文。
12. 关掉地球开关后重启，确认设置与输入卡都仍是关闭；打开设置 → 对话，确认开关、状态与费用 / 隐私说明一致。
