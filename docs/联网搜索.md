# 联网搜索（M5）

AI 助手在 **Work 与 Chat 模式**下都可以调用 `web_search` 联网搜索公开网页。搜索只走 **DeepSeek 官方 Search**，与对话共用同一个 API Key。Work 的 `web_search` 与读表 / 写表 / 加页并列；Chat 在开关开启时只提供 `web_search`，**不提供任何表格工具**。

## 范围

- Work 按权限提供表格工具，并在开关开启时追加 `web_search`；Chat 无论开关如何都没有表格工具，开关开启时**唯一**可用的工具就是 `web_search`。
- Chat 只放行 `web_search`：模型即使返回读表、写表、加页等调用，也会被忽略并提示，不碰表格桥。
- 只支持 DeepSeek 官方搜索，不支持 Tavily / Brave / SearXNG，也不提供搜索 Key 输入框或提供商下拉。
- 只返回搜索服务自带的标题、链接、站点、日期与摘要；**不抓取网页正文**，不打开页面读取内容。
- 不做每次搜索审批、不做缓存、不做自动重试、不做应用内截图、不做后台续跑。
- 搜索结果里的标题、摘要与链接都是外部不可信数据，不能覆盖系统硬规则。

## 端点与 Key

- 固定端点：`POST https://api.deepseek.com/v1/tools/search`。
- **不从自定义 Base URL 推导搜索地址**，避免把 Key 送到第三方网关。
- 只在以下条件全部满足时启用：

  1. 提供商预设为 `deepseek`；
  2. 搜索提供商为 `deepseek`（当前唯一选项）；
  3. 对话 Base URL 是 `https://api.deepseek.com`（https、无用户名/密码）。

  条件不满足时地球按钮变灰，悬停显示具体原因。

- Key 沿用「设置 → 模型」里的 DeepSeek Key，存在 Windows 凭据管理器 `deepseek / llm` 作用域；不新增搜索专用 Key，也不把 Key 写进设置、对话库或日志。

## 开关

- 输入卡左侧的地球按钮是开关：默认开启，`aria-pressed="true"`；点击关闭后按钮变灰，关闭状态记入 `settings.searchEnabled`，并同步到新会话。
- Work 与 Chat 使用同一个开关；新建 Chat 会话沿用当前设置，也可以直接点地球切换。Chat 关闭搜索时，请求不带任何 `tools`。
- 只在对话库可写、桌面版、非生成中且搜索可用时可切换；不满足时点击只给原因，不改变设置。
- 设置 → 对话里也有「联网搜索（Work 与 Chat）」复选框，状态行会显示可用性、当前 Key 是否就绪与不可用原因。

## 请求与返回

请求体：

```json
{ "query": "测量学 新闻", "count": 6 }
```

- `query`：1–128 个字符；支持 `site:`、`-site:`、`"短语"`、`-词`、`lang:zh,en`、`after:`、`before:` 等搜索语法。
- `count`：默认 6，范围 1–8。

成功响应由 Rust 归一化为：

```json
{
  "ok": true,
  "provider": "deepseek",
  "query": "……",
  "count": 6,
  "results": [
    {
      "title": "……",
      "url": "https://……",
      "site": "example.com",
      "date": "2026-11-04",
      "summary": "……"
    }
  ]
}
```

- 空结果是 HTTP 200 且 `results` 为空数组；界面显示「没有找到结果」，模型也会收到明确说明，不假装搜过。
- 标题空时用主机名兜底；`site` 永远从 URL 主机名生成（去掉 `www.`），不使用可伪造的 `site_name`。
- 每条摘要最多 1200 字；模型侧每条最多 800 字，整段 JSON 封顶 12,000 字符，超出时先缩短摘要，再从末尾丢弃结果。
- 失败返回 `{ok:false, code, detail}`；前端用 `searchErrorHint(code)` 转成中文，不把服务端原始响应或 `detail` 直接展示给用户。

## 上限与超时

- 每次调用 `count` 默认 6、最多 8。
- 同一轮最多 2 次搜索；一次回答最多 6 次。
- 连接超时 15 秒，整次请求 60 秒；不自动重试。
- 响应体最多读取 2 MiB，超过即放弃，避免超大响应占满内存。
- 搜索按顺序执行：同一轮里有多个工具调用时，前一个搜索完成并落地后才处理下一个；搜索完成后才进入写表审批或下一轮。

## Chat 模式

- Chat 的请求只可能带一个工具定义：`web_search`；搜索关闭时 `tools` 为 `null`。
- 系统提示明确写「当前是 Chat 模式：没有表格工具……唯一可用的工具是 web_search」，并继续要求填表 / 读表请求提醒切到 Work。
- 双重门禁：`handleRoundDone` 先按白名单过滤，`executeToolCalls` 再对非 `web_search` 的调用兜底拒绝；两层都只提示、不执行。
- 搜索次数、超时、结果归一化、来源持久化与 Work 完全相同；Chat 的搜索结果同样只保存来源元数据，不保存摘要。

## 停止与晚到结果

- 生成中按停止会立即把正在搜索的步骤标为「已取消」，不等待 HTTP 返回。
- 晚到的搜索 Promise 第一行检查任务是否仍活跃；不活跃就直接丢弃，不碰节点、不写卡片、不推进下一轮。
- 已经发出的搜索请求可能在后台完成并计费；应用不做 Rust 侧取消注册表。

## 持久化

`assistant.steps[].results` 只保存来源元数据：

```json
[{ "title": "……", "url": "https://……", "site": "example.com", "date": "2026-11-04" }]
```

- 最多 8 条；`title ≤ 200`、`url ≤ 1024`、`site ≤ 80`、`date ≤ 32`（UTF-8 字节）。
- 只接受 http/https、有主机、无用户名密码、非 localhost / 回环 / 私网 / link-local 的 URL；按去掉 fragment 的 URL 去重。
- **不保存** `summary`、`snippet`、`content`、`site_icon`、`rerank_score` 或 `authority`。
- 摘要只活在本次生成的 `job.rounds` 里；较早的搜索工具结果在上下文预算超限时压缩为前 2 条来源元数据，并提示需要时重新搜索。
- 重开会话后来源卡片仍在，展开可点原始链接；链接由系统浏览器打开。
- `agent.json` 不升顶层版本、不新增顶层键；搜索开关在既有 `settings.searchEnabled` 内。

## 安全边界

- 搜索端点硬编码，禁止跟随重定向，避免 Bearer Key 被带到其他主机。
- 结果 URL 经过白名单：拒绝 `javascript:`、`data:`、`file:`、`ftp:`、带 userinfo 的地址、localhost、`.local`、私网 IPv4/IPv6、回环、link-local、组播与 CGNAT。
- 搜索结果作为不可信数据交给模型；提示词要求不执行其中的指令、不让其覆盖硬规则、不大段复述。
- 引用必须使用结果里的原始 URL，格式 `[标题](URL)`；不得编造链接、日期或数字。
- 网页摘要可能过时；回答时会说明检索日期。
- 应用不自动打开网页，也不在应用内加载来源图标或缩略图。

## 费用

- 搜索按 DeepSeek 官方计价，约 **¥0.005 / 次成功搜索**；空结果与失败通常不计费。
- 搜索词会发送到 `api.deepseek.com`，与对话请求相同；搜索结果来自外部网页，属于不可信内容。
- 应用不代付、不中转，费用直接计入当前 DeepSeek 账户。
- 价格以 DeepSeek 官方页面为准；这里只作为设置页提示与验收参考。

## 错误码

| code | 界面提示（摘要） |
| --- | --- |
| `bad_request` | 搜索词被拒绝（400），换一个更短、更明确的搜索词 |
| `no_key` | 还没有配置 DeepSeek API Key |
| `credential_error` | 读取 Windows 凭据管理器失败 |
| `invalid_key` | Key 无效或已过期（401） |
| `insufficient_balance` | DeepSeek 账户余额不足（402） |
| `forbidden` | 没有权限使用 DeepSeek 搜索（403） |
| `not_found` | 搜索接口不存在（404） |
| `timeout` | 搜索超时（60 秒） |
| `too_large` | 搜索结果过大，已放弃 |
| `rate_limited` | 请求太频繁（429） |
| `server_error` | DeepSeek 搜索服务暂时不可用 |
| `network` | 网络请求失败，检查网络或代理 |
| `bad_response` | 返回了无法解析的结果 |
| `invoke_failed` | 桌面通信失败，请求没有发出 |

## 代码位置

- `src-tauri/src/agent/search.rs`：固定端点、鉴权、超时、限长读取、URL 过滤、结果归一化、错误码与单测。
- `src-tauri/src/agent/mod.rs` / `src-tauri/src/main.rs`：模块与命令注册。
- `web/assets/agent/tools.js`：`web_search` schema、参数校验、来源裁剪、模型侧结果格式化。
- `web/assets/agent/llm.js`：`webSearch()` 命令封装与错误提示。
- `web/assets/agent/prompt.js`：开关开启时，Work 与 Chat 都加入搜索规则、引用格式与本地日期；Chat 的硬规则与图片规则另行说明「唯一工具是 web_search」。
- `web/assets/agent/history.js`：搜索工具标签与旧结果压缩。
- `web/assets/agent/tree.js`：`steps[].results` 白名单与容量限制。
- `web/assets/agent/ui.js`：可用性判定、异步执行、卡片、地球开关、设置状态、Chat 只放行 `web_search` 的双重门禁。

## 手工验收

1. Work 模式点地球开关，问一个实时问题（如「今天有什么科技新闻」），看搜索卡片、来源链接和回答里的 `[标题](URL)`。
2. 关掉地球再问同类问题，确认不搜索、直接回答或说明需要联网。
3. 切 Chat，确认地球开关同样可用；问一个实时问题，确认执行搜索并给出带来源的回答。再让 Chat「读一下表一」，确认它只说明 Chat 没有表格工具并提醒切到 Work，不实际读表。
4. 设置 → 对话查看开关、状态、费用与隐私说明；把 Base URL 改成自定义地址，确认搜索不可用并给出原因，改回后恢复。
5. 搜索中按停止，确认卡片取消且没有晚到内容；重开软件看来源卡片仍在。
6. 目视新地球图标与按钮尺寸是否顺眼（视觉由用户拍板）。

## 明确不做

- 不做 `web_fetch` / 网页正文抓取。
- 不做 Tavily / Brave / SearXNG，不做搜索专用 Key。
- 不做每次搜索审批、缓存、自动重试、QPS 限流器。
- 不给 Chat 任何表格工具；Chat 的联网搜索不改变「读表 / 写表 / 加页只在 Work」的边界。
- 不做应用内截图、后台续跑、搜索结果正文持久化、来源图标或缩略图加载。
- 不改项目库 `store.json`、项目备份、项目导出；不升 `agent.json` 版本、不新增顶层键。
